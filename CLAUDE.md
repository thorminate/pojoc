# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Pojoc is a schema compiler: `.pojoc` schema files (versioned struct/enum/union/bitset/generic declarations) compile to Rust encode/decode/size-hint code for a compact binary wire format, with first-class support for evolving a schema across versions without breaking old data on the wire.

## Gotchas

- The runtime crate's package name is `pojoc`, not `pojoc-runtime` (path is `crates/runtime`) — `cargo test -p pojoc` runs it. The CLI binary is `pojoc` from package `pojoc-cli`; the LSP binary is `pojoc-lsp` from package `pojoc-lsp`.
- Building `crates/tests` requires `protoc`, `capnp`, and the `flatc` CLI on `PATH` (it round-trip-tests and benchmarks Pojoc against protobuf/Cap'n Proto/FlatBuffers/Bebop using equivalent schemas). If you only need the Pojoc compiler itself, build `pojoc-build`/`pojoc-cli` instead to skip this.
- `vscode-extension/` and `jetbrains-plugin/` bundle a **prebuilt** `pojoc-lsp` binary rather than building it — after changing `crates/lsp` (or its deps), rebuild and re-place it before the extensions pick up the change:
  - VS Code: `cargo build --release -p pojoc-lsp && cp target/release/pojoc-lsp vscode-extension/bin/pojoc-lsp`
  - JetBrains: same build, then copy to `jetbrains-plugin/src/main/resources/bin/pojoc-lsp-<rust-target-triple>` (`rustc -vV | grep host` for the triple, e.g. `aarch64-apple-darwin`) — `PojocLanguageServer.kt` matches the filename against the running arch/OS at startup, so the target-triple naming is load-bearing.

## Architecture

### The versioned schema model

The generated Rust struct reflects only the **latest** version's fields — one `struct Edge { ... }`, not one per version. Per-version `decode_vN`/`encode_vN`/`size_hint_vN` functions translate between that struct and each version's historical wire format; `SchemaLineage` (`crates/build/src/schema/ir/lineage.rs`) computes this mapping per version.

Every field has a stable `FieldId`, assigned once and preserved across renames/retypes — this is what lets lineage recognize "same field" across versions. Don't let analyzer refactors reassign these.

A named type's own evolution (`extends Foo@N { ... }`) has no `diff` keyword wrapper — the extends body's ops *are* the diff, unlike root-level fields which evolve through an explicit `diff { ... }` block.

### Generics

`type Box<T> { value: T }` / `field: Box<i32>` is monomorphized entirely at analysis time (`SchemaAnalyzer` in `crates/build/src/schema/ir/analyzer.rs`) into a synthesized `TypeId` per distinct `(template, args)` combo — codegen has zero awareness of generics, it only ever sees concrete registered types.

- `extends` is generic-aware and can cross template names, passing params through or dropping one with `_` (`type Mono<A> extends Duo<A, _>@M { - secondary }`) — every field using a dropped param must be cleaned up in that same `diff` or it's a hard error.
- `as Alias` (`Box<i32> as MyInt`) names the monomorphized type explicitly instead of the auto-mangled name (`BoxI32`); the auto-mangled name is still computed as a canonical identity, so reusing the same alias for a different `(template, args)` is rejected rather than silently misaliased.
- A field can't be retyped (`~ field: NewType`) across versions to a shape with no sound cast — `retype_is_supported` (`crates/build/src/schema/ir/analyzer.rs`) is the single source of truth for exactly which (old, new) pairings `emit_cast_value` (`crates/build/src/codegen/decode.rs`) actually knows how to convert (numeric widening/narrowing, fixed-size string/map/array/delta-array count changes, bitset→primitive, `box`/`?` wrap-unwrap, and a couple of Rust-type-identical shape swaps like `[T]`↔`[T](delta)`); everything else — including any struct/enum/union/bitset retyped to a different name — is rejected at analysis time rather than left to fail (or silently misbehave) in the generated code. Keep the two in sync when either changes. `lazy` fields are exempt entirely: they store raw wire bytes and defer to whatever the *current* schema's decode function expects when actually read, so old/new shape compatibility never comes up. See `crates/tests/schemas/edge.pojoc`'s `generic_mono_v3`/`generic_duo_v4`/`generic_mono_v5` for the pattern of adding a new field instead of retyping a struct-typed one in place.

### Strings are zero-copy (borrowed) everywhere

`string` fields decode as a **borrowed `&'buf str`** into the input buffer — there is no owned string type. A decoded value therefore borrows its buffer and can't outlive it; callers own on demand with `.to_string()`. This makes every type that transitively holds a string (or a `lazy` field) *lifetime-infected*: it carries a `<'buf>` parameter. `compute_lifetime_infected` (`crates/build/src/codegen/mod.rs`) computes the infected set over both named types and unions, and `type_info` renders infected names with `<'buf>` wherever they nest — arrays, maps, tuples, generics, imports, union payloads. `FixedString` stays `[u8; N]` (unaffected). A lifetime-infected union round-trips through serde as opaque bytes (the wire format) rather than a tagged enum representation, same reasoning as `emit_lazy_struct_serde` for structs — see `emit_lazy_union_serde` (`crates/build/src/codegen/structs.rs`). When comparing a decoded (`'buf`) value against a `'static`-built original in tests, leak the buffer so both are `'static` (see `decode_static` in `roundtrip.rs`).

### Other non-obvious invariants

- `pojoc_build::core::types::type_info()` is the single place that maps a resolved type to its Rust type/wire size/read-write-skip-size_hint function names — extend `type_info()` for a new type kind rather than branching in codegen.
- `crates/lsp/src/completion.rs` determines cursor context with its own lightweight token scanner over raw text, not a real incremental parse — it reuses the last successfully-parsed AST (`SchemaIndex`) for names/versions/etc. while scanning the live (possibly invalid mid-edit) text for where the cursor actually is.
- `crates/tests/schemas/edge.pojoc` + `crates/tests/tests/roundtrip.rs`/`helpers/mod.rs` is the "exercises everything" schema/test pair. Extend this pair for new schema-language features rather than writing a one-off `.pojoc` fixture.
- `enum`'s wire discriminant is a fixed-width `u8`/`u16`/`u32` (`ResolvedEnum::byte_width()`, `crates/build/src/schema/ir/ir_types.rs`), sized per resolved version from that version's own variant count (including the injected `Unknown`). Unlike `bitset`/`union`, there's no shared `read_foo`/`write_foo` function at all — `emit_read_expr`/`emit_write_expr`'s `Enum` arms (`crates/build/src/codegen/decode.rs`/`encode.rs`) inline the read/write logic directly at every field occurrence, so each one naturally picks up the width of whatever specific `TypeId` (version) that field is actually pinned to, with no separate per-version functions needed. This inlining is also what lets a bare `Enum`-typed field join the blastable/unchecked-read fast path (`is_blastable`, `crates/build/src/codegen/mod.rs`): the raw byte read is memory-safety-unchecked, but the `TryFrom` validity check still runs and still `?`-propagates, since decode_vN already returns `PojocResult`. An `Enum` nested inside a `FixedArray` is deliberately excluded from that fast path (`contains_enum_under_closure`) — `FixedArray`'s unchecked read builds elements via a `std::array::from_fn(|_| ..)` closure that must return the element type directly, and a fallible `?` can't cross that closure boundary.
- `union` needs the equivalent per-version-width awareness but can't get it via inlining (a payload's read/write logic is too large to duplicate at every occurrence) — so codegen instead emits a separate `read_foo_v1`/`write_foo_v1`/`skip_foo_v1`/`size_hint_foo_v1`, `read_foo_v2`/..., one per resolved union version (`emit_union_readers`/`emit_union_writers`/`emit_union_size_hints`, `crates/build/src/codegen/decode.rs`/`encode.rs`), each frozen at that version's own `ResolvedUnion::discriminant_width()` forever. This is required by `Unknown`'s job: it exists to losslessly carry a discriminant *this* resolved version doesn't recognize, so sizing the field from "how many variants exist right now" would silently corrupt exactly the values `Unknown` is supposed to preserve the instant a union crosses a width threshold. A root field's specific pinned union `TypeId` (not just its name) selects which version's codec it calls (`type_info`'s `Union` arm appends `_v{id.version}`) — a field that's never re-pinned after a `~ field: SomeUnion` diff stays on that version's variant set and width permanently; a variant added to the union afterward correctly downgrades to `Unknown` through that field (see `crates/tests/schemas/edge.pojoc`'s `action` field and its regression test in `roundtrip.rs`). Every union writer is therefore unconditionally fallible (`Error::DiscriminantOverflow` if a value's real discriminant doesn't fit that version's width) — `compute_constraint_infected` seeds every union name into the fallible set unconditionally, not just ones with constrained payloads.
- A union payload may itself have `lazy` and/or `intern` fields (see `crates/tests/schemas/edge.pojoc`'s `RichPayload`/`Payload::Rich`). `lazy` support required generalizing it beyond the root schema's per-version `decode_vN`/`encode_vN` (the only place it worked before) into any named type's own nested `read_foo`/`emit_type_readers` (`crates/build/src/codegen/decode.rs`) — `write_foo`/`size_hint_foo` (`encode.rs`) already handled it generically. `intern` needed the shared string table threaded through the union codecs too, but the two directions need *different* infection criteria, tracked as two separate per-`TypeId` (not per-name) sets: `UNION_INTERN_INFECTED` (read side) reflects only a version's own historical variants, since `read_foo_vN` can only ever decode discriminants that version could have produced; `UNION_WRITE_INTERN_INFECTED` (write side) reflects the *latest* variant set filtered by that version's width, since `write_foo_vN`'s match is exhaustive over the one Rust enum shape and can be asked to encode a variant only a later version declared, as long as its discriminant still fits the old width (`crates/build/src/core/types.rs`, `compute_union_version_intern_infected`/`compute_union_write_intern_infected` in `crates/build/src/codegen/mod.rs`). The root's own `version_uses_intern` must use the write-side (broader) criterion for a `Union`-typed field, since the intern-table-on-the-wire flag is a single per-version bit that encode and decode of that version must agree on.
